## Goal
Close the loop from `docs/FLOW.md` §1 and §4. Plan a **saved list** with the household's **saved offers**, keep the result, accept one plan
→ it becomes **baskets** (ready or pending). Then the user marks each basket placed (actual amount paid), records cashback received,
or releases a pending basket whose deadline passed. A ledger summary shows what was paid and what offers were captured this month.

## Runtime boundary
Server-side. The optimizer is called **only** through `run_plan`. Offer `uses_left` is decremented **only** when a basket is placed.
Money is int paise. Times come from `clock.now()` (never `datetime.now()` directly).

## Endpoints (prefix `/api/v1`, `baskets.router`. The lead wires it.)
1. `POST /lists/{list_id}/plan` `{members?, fillers?, max_filler_gap_paise?, rho_bp?}` → builds a `PlansRequest` from the list's
   **open** needs (need.line_id, keys, quantity, qty, need_by, lock) and the household's **active** offers (not archived, `uses_left > 0`,
   `valid_to` null or ≥ today by `clock.now()`), runs `run_plan`, stores a `plan_run`, and returns `{plan_run_id, ...PlansResponse}`.
   A list with no open needs → 422.
2. `POST /plan-runs/{id}/accept` `{label}` → creates one basket per order of that labelled plan: `status = "pending"` for the pending
   order, `"ready"` otherwise. Lines are copied from the stored response. `need_id` is matched by line_id within the list. Needs on accepted
   lines → `status = "planned"`. Sets `accepted_label`. Unknown label → 422. Already accepted → 409. Returns the baskets.
3. `GET /baskets?status=` → household baskets with lines, newest first. `GET /baskets/{id}`.
4. `POST /baskets/{id}/place` `{actual_paid_paise, without_offer?: bool}`
   - From `ready` → `placed`. From `pending` only with `without_offer: true` (else 409). Then `offer_value_expected_paise = 0`.
   - For each applied offer code on a placed-with-offer basket: decrement that household offer's `uses_left` by 1 (not below 0).
   - Need lines → `bought`. Sets `placed_at`. `actual_paid_paise < 0` → 422. Any other status → 409.
5. `POST /baskets/{id}/cashback` `{received_paise}` → only from `placed` → `settled`, sets `offer_value_received_paise` + `settled_at`.
6. `POST /baskets/{id}/release` → only from `pending` → `released`. Its non-filler needs go back to `open`.
7. `POST /baskets/{id}/lines` `{listing_id, line_id}` → only on `pending`: adds a filler/extra line (seed listing price for the plan_run's
   members, `packs 1`). Recomputes subtotal → if subtotal ≥ the stored threshold for the target offer, status → `ready` and
   `shortfall_paise` → 0, else `shortfall` = threshold − subtotal. (Store `threshold_paise` on the basket for this. Add the column.)
8. `GET /ledger/summary?month=YYYY-MM` (default: current month by clock) → `{placed_count, paid_paise, offer_expected_paise,
   offer_received_paise, cashback_pending_paise}` over baskets placed in that month.
